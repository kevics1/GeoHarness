# 两个可复现的审图与效率验收案例

使用实际运行 `geoh` 的 Python 生成新目录，不覆盖旧测试：

```powershell
python examples/review_acceptance/generate_cases.py F:/Desktop/GeoHarness-review-cases
```

生成器只创建合成 GIS 数据及独立答案，不调用模型。输出目录已存在会拒绝写入。
每个案例的 `expected.csv` 按真实 `entity_id` 给出最近避难所、距离与重点标记，
`expected.json` 给出数量与缺失值，供测试后独立核对；不要把这两个答案文件当分析输入。
两个目录分别启动新的 `geoh run`，避免任务之间共享审图额度。

## 简单案例：单页最近避难所分析

在 `simple` 目录启动，发送：

> 读取 residents.gpkg 和 shelters.gpkg。以 entity_id 为稳定主键，在米制投影中计算每个居民点
> 最近的避难所、名称和距离，严格以距离小于500米标记重点。不得用行号关联。
> 输出完整分析结果和一张中文总览图，图上包含居民点、避难所、清楚的图例及比例尺。
> 居民点呈狭长分布，Page.layout.fit使用frame，保持合理图框并向外扩展显示范围，不改真实坐标。
> 不要求逐点编号，完整属性保存在结果数据里。使用原生制图，只在严重像素缺陷时返修，
> 轻微拥挤、留白和配色建议不触发重审。审查通过后，最后一次生成可编辑QGIS工程并交付；
> 如达到审图上限仍有严重问题，停止并说明剩余问题，不声称通过。

核对：20个居民点、3个避难所、2个重点，无人口缺失；最近距离逐实体与答案一致。
只需1页及1次首审；没有严重问题应直接进入交付，同一图重复审查应命中缓存。
每页最多3次实际图片请求。记录模型请求数、实际图片请求数、重绘次数、总耗时及最终状态。

## 复杂案例：混合CRS、多时次、多页与缺失值

在 `complex` 目录启动，发送：

> 输入为 residents.gpkg、shelters.gpkg、roads.gpkg、fire.gpkg 和 dem.tif。
> 审查CRS、字段和缺失值后，在米制坐标中计算最近避难所和距离、最近道路距离、DEM高程，
> 保留原人口字段及真实缺失值，不插补。用 entity_id 关联，不用行号。
> 最近避难所距离严格小于500米为重点。火场按hour的1/2/3时次分别表现，不把时次当毫秒值。
> 使用原生制图做4页：1页总览、1页重点详图、2页完整名册（每页60行）；总览不要求逐点编号，
> 详图仅标注重点对象，名册保留全部120条，包含真实ID、人口、最近避难所、距离及高程。
> 总览画出详图实际范围定位框，图例与各页实际内容对应。一次审查全册，只修改严重缺陷，
> 未变页面复用报告。不得为审图另造坐标或标签数据；允许轻微留白与风格差异。
> 全部必要检查通过后，最后一次生成可编辑QGIS工程并交付。达到上限仍有严重问题时停止，
> 保留草稿、报告和未解决问题。

核对：120个居民点、4个避难所、2条道路、3个火场时次；人口缺失3条，DEM高程缺失1条。
最近避难所和严格阈值重点数量见独立答案。不得将缺失人口/高程填0或在后续处理中丢失已有字段。
正常首审4次。首次通过后，可另发“只修改第2张名册标题为‘居民点名册（续）’，其他不变”；
新增图片请求应只有1次，其余3页复用，随后按新候选交付一次工程。
全任务最多12次、每页位最多3次实际图片请求，失败也计数；单轮批量工具调用不等于1次图片请求。

## 停止与质量核验

- `warning/info`保留在报告中，不进入自动返修、待修阻断或额外审查。
- 真正主图空白、主要主题缺失、大面积重要内容不可读或图例严重误导应报`error`。
- 上限后不得再发新图片请求或重绘；未解决严重问题不允许正式交付，缓存报告仍可读取。
- 时间只记录实测值，不因20分钟目标而减数据、隐藏缺陷或强行通过。
- 合成数据、离线客户端计数测试、实际视觉服务检查和完整主模型对话验收分别记录，不能互相替代。
