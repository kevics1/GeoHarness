## 合并问题与已写规则

| 问题 | 调用前规则 |
|---|---|
| Path/i未定义，沿用前次变量 | 每次新进程都重新import/定义名称 |
| label/gid/风险字段/汇总JSON键不存在 | 检查实际中间对象字段、merge后缀、结果键，不猜字段 |
| Timestamp被切片、JSON结果包含原生对象 | 核对类型；日期isoformat，NumPy标量item，数组tolist，Path转str，缺失转None |
| 假data引用、Windows控制字符、目录/manifest混用、未绑定读取 | 引用原样复制；input_refs绑定真实文件；正斜杠或原始字符串；目录与文件分别处理 |
| 缓冲/叠置自交、距离先取整 | 输出前核实几何；原值保留精度，只在显示时格式化 |
| extent与focus_layers同时传，名册coverage，未知模板字段 | 首次render前统一核对页面互斥字段；使用真实Schema允许的占位符 |
| 分类字段不存在、select_keys和label_offsets_mm使用排名/图层ID | 每层核对实际字段及key值/类型，标签偏移以真实实体key字符串索引 |
| 分析输出未真正映射、辅助图层没有事实绑定 | 已发布原生产物直接作为图上source_ref；真正新增派生矢量提前发布 |
| 复制子集/事件/标签点导致来源无法证明、字段退化 | 子集用原层+select_keys，背景用原来源，文字偏移用内置功能，不伪造成员或删除理由 |
| 未绑定Python读取scene-plan或glob报告 | 查看已有计划用geo_cartography inspect，不增加受保护文件探查 |

共同原因判断：规则分散且较晚报错，模型临时复制/删字段/补发布后又触发下一层来源契约。
将规则放到主提示词、两个工具的调用帮助以及相关字段Schema中，比仅增加一条泛化“谨慎调用”更直接。
分析/成员/几何检查发现的不一致仍需修正；不能以屏蔽报错来替代正确分析。

## 真实调度缺陷

OpenHarness会为同批每个工具浅复制metadata；原实现首次在该副本创建锁字典，使同任务调用
各拿一把锁并争抢OS执行锁。测试复现maximum=2，而非期望的1；已改为按事件循环与任务目录
共享的进程内弱引用锁，使合法同批调用排队，不关闭跨执行器互斥。
