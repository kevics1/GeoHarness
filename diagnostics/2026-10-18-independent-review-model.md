# 独立图片审查模型配置与超时诊断

## 实现范围

- `map_review.model/base_url/api_key` 可直接在用户 `config.yaml` 中修改；空字段分别继承主配置对应项。主模型和主会话思考策略不受影响。
- 用户现有配置补充了独立服务字段、返回格式和说明；迁移时核对所有原值保持不变，并在用户配置目录留存备份。后续用户自行修改的模型及思考配置原样保留。
- `response_format: tool` 保持函数调用；`json` 使用 JSON object 文本，同一结构校验，不自动切换模型、思考强度或返回格式。
- 思考强度与返回格式忽略大小写及两端空格；模型标识不做规范化。更改配置后需重新启动已运行的会话。
- 新增 `geoh review-doctor`：默认只查看脱敏配置；`--live` 发送一次随机图片能力测试；`--live --image` 只审查指定图片。诊断不渲染地图、不写业务地图台账。
- 审图流记录事件数、时间、字符数、usage、完成标记，不保存思考正文。总时限到达区分生成阶段与响应收尾，避免一律归为网络故障。
- 配置及返回格式进入审图缓存指纹；配置变更后重新审查。

## 实际调用证据

业务地图回放使用同一页的整页及局部共 5 张图片，未重绘或修改业务地图。

| 请求 | 结果 | 观察与限制 |
| --- | --- | --- |
| 原模型、max、131072 输出上限、180 秒总时限 | 181.578 秒后未完成 | 33472 个流事件、132882 个思考字符、没有回答或函数参数；最大事件间隔仅 0.359 秒。证据指向持续生成触及总时限，不能据此称为网络断流。 |
| 相同请求内容，仅将本地时限设为 300 秒 | 149.25 秒完成，返回 issues | 一次随机观测；无法证明延长时限能稳定解决问题。 |
| 用户改为独立 none 模型别名后，同图、同 5 张图片 | 11.578 秒完成，返回 issues | 客户端仍发送 max，但服务返回 reasoning tokens 为 0；不能宣称服务端执行 max，审查准确性仍需另验。 |
| 用户改为独立 Medium 模型别名后，随机数字和颜色/形状小图 | 6.156 秒完成 | 成功读出未写入提示词的随机六位数字与三组颜色/形状；返回 187 reasoning tokens。只证明该次图片输入与结构化返回可用。 |

最后一次离线配置核对读取用户目录的 `config.yaml`，模型来源为 `map_review`，服务与凭证来源为主配置，思考参数为 medium，无配置错误。模型值来自用户编辑，工具未自动选择或降级模型。

业务原始回放目录在前述实测后已不存在，后续指定该旧图片路径的诊断失败属于缺失文件，不算视觉服务失败。未重建或猜测业务输入。
