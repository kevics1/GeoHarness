# 最新测试审查及非 QGIS 制图流程重构方案

日期：2026-10-19。第1–5节记录实施前的只读诊断和方案；用户随后授权实施。当前代码改动、验证结果和外部服务限制见文末，原始数据与旧交付保留。

## 1. 纠正目标

用户现已明确：数据获取→数据审查→空间分析→非 QGIS 原生制图→原生图片审查通过→准备交付时一次生成可编辑 QGIS 工程。

标准空间分析可以继续使用 QGIS Processing，`geo_python(backend=qgis)` 作为分析控制台。制图、修图、排版与预览不得启动 QGIS；QGIS 在制图链中只作为最终工程导出器。不能将“不写 qgz 的内存 QGIS 渲染”称为已符合这个目标。

旧诊断将用户要求解释为内存 QGIS 预览，旧实现与测试也按这个解释验收，这是方向性偏差。旧工程测试仍能证明其测试过的行为，但不能证明新目标实现。

## 3. 已核实的问题

### P0：工作流责任放错，正式交付没有审查准入

`cartography.static_renderer`仍默认qgis，提示词优先spec/build，制图输入以QGIS图层/布局API为中心。模型要先学会工程式参数、帮助分页和冻结引用，才能完成本应由渲染器完成的排版。

首次交付v6时主图/详图仍issues，工具已经生成工程；之后又审名册、改名册、生成第二套工程。最终v8总体unverified仍允许交付。这不是同一冻结版本幂等失效，而是没有在进入工程阶段前冻结“所有必要页面已通过、问题已处置”的交付候选。

### P0：衍生字段在重算时丢失，最终文字仍引用旧版本

早期`settlement_metrics`输出234行，`elev_m`缺失4行。`metric_fix_4543`从原始pts重建，使用`g['elev_m'] if 'elev_m' in g else np.nan`，没有重新采样DEM或按gid连接旧抽样，最终交付234行高程全部为空。最终答复仍称4处缺高程。

事实包只声明距离和人口字段，未声明高程，因此统计自洽检查没有发现衍生字段退化。解决方向必须是分析结果的字段契约、来源依赖及缺失值变化检查，而非只给某个脚本增加提醒。

独立测量确认：本轮最终234条蔓延距离、避难距离、避难场所名称均一致，无上一轮错行；2/11/9/62/150计数一致。原数据及伴随文件SHA未变。这不认证所有方法、道路通行、设施容量或风险等级业务依据。

### P1：审查次级页制造了不存在的新地图版本

15:55:40对旧预览的`roster_page_3.png`审查，台账新增v7，将这张名册当成主图；该版本无工程、无数据/布局检查。它没有对应新一次渲染。

当首次交付把package绑定迁到最终工程目录后，旧预览页的归属定位失败，审图入口降为单图登记。完整页面关系应按map/page/revision持久绑定，不能只靠当前package目录或主图哈希猜测；审图是观察，绝不能创建地图版本。

### P1：未变页面审查不能跨版本继承

v6与后续改名册版本的主图SHA均为`ca01f474...985939`、详图SHA均为`f895db5c...c15f0c`，逐文件完全相同。最终v8仅保存page_index=2的passed，主/详图审查没有继承，全册unverified。其余页仍有问题，不能继承为通过；但也不能把已知issues抹成未检查。

### P1：问题追踪形式存在，缺少实际处置

15份审查的repair_progress全部not_established。共42条观察均有bbox，但缺少稳定要素身份，措辞/ROI变化导致匹配分裂。任务最终27条待处置记录为22 needs_recheck、5 open，没有有效confirmed/dismissed/fix_verified闭环。这是历史记录数量，不等于27个独立地图缺陷。

读图意见还包含证据越界：“听涛谷·众书房”名称似乎不像学校，于是猜类型错位；核对源记录可知reclass沿用源数据。单位重复属于格式一致性建议，不应和漏行、遮挡、真实单位错误同级阻断。图片审查工具可以原样报告疑点，但系统必须判断证据范围与影响，不能把每条意见直接变成全册重画指令。

### P1：分析输入接口相互矛盾，静态检查误拦截

- 已给`input_refs.fire`，`read_vector('fire')`仍被managed_inputs当作未登记全局名，代码只匹配bindings.values而非alias键。
- 动态resolve_data循环虽然能找到目录名，文件读保护只认可声明输入，造成脚本启动后才报权限错误。
- `INPUTS['ev'] if False else None`中的不可达读取也被ast.walk判为缺输入，虽未执行仍硬失败。
- 名称/路径/data引用/INPUTS别名并存；模型必须记住不同助手的不同规则，增加错误面。

### P1：同一模型批次自相冲突，错误提示误称另一执行器

同一assistant批次同时发geo_python和publish_analysis，后者报“当前任务正在由另一执行器运行”。submit_plan先于run_plan的asyncio.Lock取得OS执行锁，合法同会话并发在排队前失败。不是用户另开会话的证据。应由调度器统一排队状态写入、明确依赖，并区分等待、前置未就绪、外部占用与失败。

### P1：帮助与数据契约成本很高，失败恢复没有收敛

18次help中有多轮schema/properties分页，edits帮助形状不同导致路径失败。headers需要字典却传列表，labels编辑缺必填label_field，patch使用了错误operation，两个相同冻结请求重复失败。说明字段虽有描述，模型仍在操作过宽、结构不一致的Interface。

分析报告/生产者manifest/结果包report.json路径也被混用，导致“Only known geo_analysis native manifests are supported”；随后删manifest又触发缺事实包，再临时补原生分析。一处结果引用应由系统绑定，不能要求模型分别搬运多种清单路径。

### P1/P2：自由脚本承担标准分析与版面准备，重复计算和字段漂移

25次Python中8错，包括sindex.nearest输入维度/类型错误、dist_band字段不存在、Polygon误用total_bounds、依赖fiona不存在。标准距离、范围、单位、实体关联与schema应走稳定分析接口；Python保留真正扩展需求。

模型最初用不适合位置的EPSG:4547，再改4543；补做原生分析用默认32648。最终页脚展示计量32648，核心Python事实声明4543，累计两个方法被混合呈现。相同分级计数不能证明两套距离与过程完全等价，应逐结果记录实际计算CRS、参数和验证范围，不能回退统一配置掩盖差异。

### 呈现问题与误判边界

已看最终三页：总览密集点确实难逐点区分，详图编号有贴近；但这不足以证明“160米间距在任何方案下都无法标清”。移动文字、引线、局部小图或分区详图都可在保留真实点位的前提下改善。总览不应被要求逐个辨认全部234点，详图/名册负责重点22点对应。

时序面颜色与图例样例受到透明度、嵌套覆盖和底色影响；需要在渲染计划中明确累计面顺序或展示差分环带、统一图例。不可修改原分析几何来迎合图片。不能仅凭当前缩图认证具体分类错绘。

## 4. 完整修复方案（待实施）

### 4.1 一条阶段状态链，系统决定准入

`数据获取 → 输入审查 → 分析 → 结果验证 → 制图 → 审图 → 交付候选冻结 → QGIS工程编译 → 交付`

分析阶段仍可调用QGIS Processing；从进入制图开始到候选冻结，不允许制图工具或自由脚本启动PyQGIS/工程写出。正式工程生成必须持有当前候选许可，绑定结果版本、全部页计划/图片和审查判定；许可随相关数据/页面修改失效。没有许可时返回缺少的前置条件，不调用导出器。

未通过时保留图片和分析草稿，默认不生成工程、不称正式交付。只有用户明确要求提前拿工程修改时，走显式草稿导出例外，并独立标识；不能让模型自行批准绕过。保留已有工程的用户显式编辑场景，不混入新制图主流程。

### 4.2 一个完整分析结果引用

复用现有结果包/SQLite任务数据，输出一个版本化analysis_ref（拟议统一语义，具体接口实现时确定）。包含原始引用/哈希、真实算法/参数/计算CRS、唯一实体键、字段/单位/缺失政策、完整与重点对象集及事实表。

标准QGIS分析输出可直接成为结果包；Python扩展也通过同一结果发布出口。地图与报告只接收结果引用，不分别手工传事实报告、生产者manifest和源数据路径。依赖分析字段必须保留或声明重算/移除原因，字段全空、行数异常、实体丢失阻断该结果晋升。阈值先分级再舍入展示；位置与坐标操作适用范围在执行前检查。

### 4.3 一个与QGIS无关的已解析制图计划

复用现有spec/page cache/结果事实，抽离出与QGIS无关的类型模型：页面职责、图框、来源与选集、样式/顺序、地图CRS/范围、毫米/字号、图例、表格、已解析文字内容和标注锚点。结果引用与业务ID是唯一来源，不从文件名猜。

计划同时保存渲染后的实际字体/位置、标签bbox与引线、图例样例色、表格行/排序/单位和页面依赖。这样标签放置只决策一次；工程导出阶段不能重新自动排版。

两条Adapter消费同一计划：

1. 原生渲染：复用现有`cartography/renderer.py`的Matplotlib Agg与静态导出能力，补齐多页、详图、表格、稳定标注；输出PNG/PDF/SVG，不调用QGIS，不写qgs/qgz。
2. 最终工程：只在冻结后用PyQGIS把计划编译成真实图层、样式、图框、标签/引线和布局表格；不由模型再写一套布局参数。

**不能只把static_renderer改为matplotlib。** 现有`cartography/project.py`导出的仅为reference，自己声明不能复现全部自定义注记；geo_cartography还存在attach_project路径，仍可能提前产工程。必须把这些出口统一迁到最终编译器，并使正常制图Schema不再依赖QgisProjectLayout/help。

复用现有Matplotlib，不为此新增另一套地图框架。官方Agg后端及许可证已核对；QGIS只调用已安装的接口，不复制其上游源码。

### 4.4 页面是稳定对象，审查是观察

保留稳定page_id及其revision，页计划/像素/字体与来源哈希决定失效。审次级页不能新增地图版本；候选引用包中的每一页，无论路径处于预览目录还是最终工程目录。

未变页可继承完整passed/issues状态和报告来源；变更页才重审。像素结论复用与分析/来源认证分开：图片不变可沿用视觉观察，数据来源改变仍须重新验证事实，不自动继承全部质量。无需反复让模型逐页猜路径，审图工具只读任务已登记的受影响页面。

### 4.5 审图只找问题，系统负责处置与修复

geo_map_review保留原生图片输入，输出问题、位置、证据范围和限制；不增加自动修图、造数据或触发QGIS功能。

系统侧把意见区分为已证缺陷、待核实疑点、表达建议。像素证据不能证明数据分类语义。疑点通过已绑定来源核对，仍未知且影响业务时直接问用户；不猜测。格式建议不自动成为硬失败；是否构成阻断由明确页面验收规则决定。

issue关联结合page_id、frame/区域与要素ID、可定位bbox，允许模型措辞变化，仍保留匹配依据。新图未报告旧问题不自动算已解决；已确认问题通过定向区域复核与明确处置闭环。对重复问题记录采取的策略、可测改善与失败原因；无改善时换策略或询问必要取舍，不继续微调同一字号。

制图前先完成确定性文字bbox/页边/名单行数/数值单位/图例和符号检查，再请求图片服务。没有精确支持的符号不假称已通过。密集点保真、文字可移动并带引线；必要时自动增加局部详图；是否聚合业务对象须有明确政策或询问。

### 4.6 最终工程一致性，而非把PNG粘进工程

分析结果与已审原生地图为权威成品，QGIS工程是同一冻结计划的可编辑版本，必须带真实地理图层和可编辑布局。

跨Matplotlib/QGIS字体和抗锯齿不能承诺字节级相同。工程编译后，系统只做一次兼容验证：图层/选集/CRS/几何、分类及图例值、图框、文字和编号位置、表格全部行对齐；必要时在本次导出作业内离屏渲染校对可见差异，不更换已审原图。如果出现实质差异，保存证据、停止正式发布，不能继承原图passed给不同的QGIS图片，也不能进入无限生成/审图循环。

工程以候选ID+内容摘要幂等缓存；重复交付复用，打包/复制不是再生成。写入前意图日志、原子发布、崩溃恢复依据真实产物与校验证据，不靠删除锁或未知状态下盲重建。物理写入中断不应虚称具备绝对exactly-once保证。

### 4.7 简化模型可见调用面，执行与证据单次登记

数据工具一次返回引用/字段/CRS/数量/缺失摘要；标准分析返回完整结果引用。制图只暴露建计划、按稳定ID增量改动、渲染/查看等少量操作（名称待实现确定），复杂内部QGIS Schema不随每轮发给模型。

帮助返回统一结构、完整最小调用、字段类型与合法动作，分页沿真实返回的continuation调用，避免手猜schema/properties。字段错误返回实际字段摘要和局部修改入口；不反复输出整个工程Schema。

同任务变更操作统一排队，前置依赖由系统解释；独立只读操作可并发。每次执行只保留一个权威operation/result，外层计时可关联，不能把内外包装当成新进展。正常回执仅含状态、引用、变化、必要诊断和下一步；完整证据按需读取。阶段变化按真实产物和语义差异，路径变化/新execution_id不算进展。high和视觉模型配置保持。

## 5. 实施顺序与验收

1. 先冻结真实失败样例，补阶段准入、次级页身份、并发排队和字段退化保护；不先移除QGIS能力导致功能空档。
2. 实现统一制图计划与原生渲染Adapter，以最新三页的全量/重点/名册对象验证功能覆盖，QGIS不可用时仍能完整制图与图片审查。
3. 实现从同计划生成工程的Adapter，逐项验证可编辑性/一致性后切换默认流程，旧路径保留显式兼容入口。
4. 接入问题处置、页面增量审查、最终候选许可；更新中文Schema、帮助、系统提示及指南，移除相互矛盾的主路径引导。
5. 构建最终wheel、核对实际安装、CLI后，用同一实际主/视觉模型进行业务对照，统计各阶段时间、模型往返、错误恢复和最终质量，保留失败证据。

必要验收条件：

- 分析结束后到审查通过之前，制图进程不得调用QGIS，磁盘无新qgs/qgz；QGIS禁用仍可制图/审图。
- issues/unverified不能走正式工程生成；正确通过后一次生成，同版本重复/重启复用。
- 不支持的工程表达必须在制图计划阶段明确，不能临交付静默降级成截图或参考工程。
- 修改名册只失效名册；审其他页不新增版本；已知issues不能消失为unverified。
- 标准分析输入别名、静态不可达代码、同批次依赖/并发、错误恢复不再产生本轮已复现失败。
- 234行最终距离正确且字段完整，旧高程4缺失不能无声明变234；最终文字只读当前事实表。
- 旧数据、旧交付、模型high、视觉配置和凭证保持；20分钟为真实效率目标，不引入硬截停或伪造质量通过。

以上为实施前的诊断和目标；实际实施情况及验证边界见文末，不以旧QGIS预览测试代替新流程验收。
